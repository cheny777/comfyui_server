# ComfyUI 图像生成服务系统设计文档

## 1. 项目概述

### 1.1 项目背景
本项目旨在构建一个分布式的 ComfyUI 图像生成服务系统，通过前台和中台分离的架构，实现用户认证、任务管理和图像生成服务的解耦。

### 1.2 系统目标
- 默认游客模式，无需注册即可使用
- 自动识别和记住用户信息，实现多用户隔离
- 通过中台统一管理 ComfyUI 任务调度和图像生成
- 提供图像文件存储和访问服务
- 支持前台（公网）和中台（内网）的 WebSocket 实时通信

### 1.3 技术栈
- **前台前端**：HTML + CSS + JavaScript（原生或Vue/React）
- **前台后端**：Go + Gin框架 + WebSocket Server + JWT认证 + SQLite数据库
- **中台服务**：Go + WebSocket Client + HTTP Client + 文件服务器 + SQLite数据库（记录生成请求）
- **ComfyUI**：Python 图像生成服务

### 2.2 架构说明

#### 2.2.1 前台服务（Front Server）
- **部署位置**：公网服务器
- **主要职责**：
  - 用户识别和会话管理（自动创建游客用户）
  - Token 管理（基于设备ID/Session生成）
  - 接收用户请求，转发给中台
  - 维护与中台的 WebSocket 连接池
  - 实现用户级别的数据隔离
  - 记住用户信息和历史记录

#### 2.2.2 中台服务（Middle Server）
- **部署位置**：内网，与 ComfyUI 同机或同网段
- **主要职责**：
  - 主动连接前台 WebSocket 服务
  - 管理 ComfyUI 连接（HTTP + WebSocket）
  - 接收前台任务请求，提交到 ComfyUI
  - 监听 ComfyUI 任务执行状态
  - 下载并存储生成的图像
  - 提供图像文件访问服务

#### 2.2.3 ComfyUI 服务
- **部署位置**：内网
- **接口**：
  - HTTP API：`/prompt`（提交任务）、`/history`（查询历史）、`/view`（查看图像）
  - WebSocket：`/ws`（实时状态推送）

## 3. 模块设计

### 3.1 前台服务模块

#### 3.1.1 用户识别与管理模块
**功能**：
- 自动识别用户（通过设备ID、浏览器指纹或Session）
- 首次访问自动创建游客用户
- 生成并管理用户 Token（JWT）
- 记住用户信息和历史记录
- Token 验证和刷新

**用户识别机制**：
1. **设备ID方式（推荐）**：
   - 客户端首次访问时生成唯一设备ID（UUID v4），存储在LocalStorage中
   - 设备ID持久化存储，即使清除Cookie也能识别用户
   - 如果LocalStorage不可用，降级到Cookie存储
2. **Session方式（备选）**：
   - 使用Session ID识别用户，存储在Cookie中
   - 适合不支持LocalStorage的环境
3. **浏览器指纹（辅助）**：
   - 结合User-Agent、IP、屏幕分辨率等信息生成唯一标识
   - 作为设备ID的补充验证

**用户信息记忆机制**：
- **自动创建**：首次访问时自动创建游客用户记录
- **持久化存储**：用户信息、任务历史、偏好设置都存储在数据库中
- **跨会话记忆**：用户关闭浏览器后再次访问，通过device_id自动识别并恢复信息
- **信息同步**：每次用户操作时更新last_active_at，保持用户活跃状态

**数据结构**：
```go
type User struct {
    ID           int64     `json:"id"`
    DeviceID     string    `json:"device_id"`     // 设备ID（客户端生成）
    UserType     string    `json:"user_type"`     // guest（游客）、registered（注册用户）
    Nickname     string    `json:"nickname"`      // 用户昵称（可选，游客可自定义）
    Avatar       string    `json:"avatar"`        // 头像URL（可选）
    LastActiveAt time.Time `json:"last_active_at"` // 最后活跃时间
    CreatedAt    time.Time `json:"created_at"`
    UpdatedAt    time.Time `json:"updated_at"`
}

type UserInitRequest struct {
    DeviceID string `json:"device_id"` // 客户端生成的设备ID（可选，服务端可自动生成）
    Nickname string `json:"nickname"`  // 用户昵称（可选）
}

type UserInitResponse struct {
    Token string `json:"token"` // JWT Token
    User  User   `json:"user"`
}
```

**API 接口**：
- `POST /api/user/init` - 初始化/获取用户（自动创建游客用户，如果不存在）
- `GET /api/user/info` - 获取当前用户信息（需要 Token）
- `PUT /api/user/profile` - 更新用户信息（昵称、头像等，需要 Token）

#### 3.1.2 WebSocket 服务模块
**功能**：
- 接收中台的 WebSocket 连接
- 维护连接池（按中台实例ID管理）
- 消息路由（用户请求 → 中台，中台响应 → 用户）
- 连接心跳检测

**连接流程**：
1. 中台启动时主动连接前台 WebSocket
2. 中台发送认证消息（包含中台ID、密钥等）
3. 前台验证后建立连接，加入连接池
4. 定期心跳保持连接

**消息格式**：
```go
type WSMessage struct {
    Type      string      `json:"type"`       // 消息类型
    RequestID string      `json:"request_id"` // 请求ID（用于匹配请求响应）
    UserID    int64       `json:"user_id"`    // 用户ID（用于用户隔离）
    Data      interface{} `json:"data"`       // 消息数据
}

// 消息类型
const (
    MsgTypeAuth          = "auth"           // 中台认证
    MsgTypeHeartbeat     = "heartbeat"      // 心跳
    MsgTypeTaskSubmit    = "task_submit"    // 提交任务
    MsgTypeTaskStatus    = "task_status"    // 任务状态
    MsgTypeTaskProgress  = "task_progress"  // 任务进度
    MsgTypeTaskComplete  = "task_complete"  // 任务完成
    MsgTypeImageReady    = "image_ready"    // 图像就绪
    MsgTypeError         = "error"          // 错误消息
)
```

#### 3.1.3 任务管理模块
**功能**：
- 接收用户任务提交请求
- 任务队列管理（按用户隔离）
- 任务状态跟踪
- 任务历史记录（记住用户的所有任务）
- 用户偏好设置记忆（如常用工作流、默认参数等）

**数据结构**：
```go
type Task struct {
    ID          string                 `json:"id"`
    UserID      int64                  `json:"user_id"`
    Workflow    map[string]interface{} `json:"workflow"`
    Status      string                 `json:"status"`      // pending, running, completed, failed
    PromptID    string                 `json:"prompt_id"`  // ComfyUI prompt_id
    Progress    int                    `json:"progress"`   // 0-100
    Images      []string               `json:"images"`     // 生成的图像URL列表（从files表查询）
    Files       []File                 `json:"files"`      // 文件详细信息列表
    Error       string                 `json:"error,omitempty"`
    CreatedAt   time.Time              `json:"created_at"`
    UpdatedAt   time.Time              `json:"updated_at"`
    CompletedAt *time.Time             `json:"completed_at,omitempty"`
}

type File struct {
    ID              int64     `json:"id"`
    TaskID          string    `json:"task_id"`
    UserID          int64     `json:"user_id"`
    Filename        string    `json:"filename"`
    OriginalFilename string   `json:"original_filename"`
    FilePath        string    `json:"file_path"`
    FileSize        int64     `json:"file_size"`
    FileType        string    `json:"file_type"`
    Width           int       `json:"width,omitempty"`
    Height          int       `json:"height,omitempty"`
    URL             string    `json:"url"`
    CreatedAt       time.Time `json:"created_at"`
}
```

**API 接口**：
- `POST /api/tasks` - 提交任务（需要 Token，自动关联用户）
- `GET /api/tasks` - 获取任务列表（需要 Token，仅返回当前用户的任务，记住用户历史）
- `GET /api/tasks/:id` - 获取任务详情（需要 Token，用户隔离）
- `DELETE /api/tasks/:id` - 删除任务（需要 Token，用户隔离）
- `GET /api/user/history` - 获取用户历史统计（任务总数、完成数等）

**JavaScript核心功能**：
```javascript
// API基础配置
const API_BASE = '/api';
let token = localStorage.getItem('token');
let currentTaskId = null;

// 初始化用户
async function init() {
    await ensureUser();
    loadHistory();
}

// 提交生成任务
async function submitTask() {
    const positivePrompt = document.getElementById('positivePrompt').value;
    const negativePrompt = document.getElementById('negativePrompt').value;
    
    if (!positivePrompt.trim()) {
        alert('请输入提示词');
        return;
    }

    // 构建工作流（简化示例，实际需要完整的工作流JSON）
    const workflow = buildWorkflow(positivePrompt, negativePrompt);
    
    try {
        const response = await fetch(`${API_BASE}/tasks`, {
            method: 'POST',
            headers: {
                'Content-Type': 'application/json',
                'Authorization': `Bearer ${token}`
            },
            body: JSON.stringify({ workflow })
        });
        
        const result = await response.json();
        if (result.code === 0) {
            currentTaskId = result.data.task_id;
            showProgress();
            listenTaskStatus(currentTaskId);
        }
    } catch (error) {
        console.error('提交任务失败:', error);
    }
}

// 监听任务状态（WebSocket或轮询）
function listenTaskStatus(taskId) {
    // 使用WebSocket或轮询获取任务状态
    const interval = setInterval(async () => {
        const response = await fetch(`${API_BASE}/tasks/${taskId}`, {
            headers: {
                'Authorization': `Bearer ${token}`
            }
        });
        const result = await response.json();
        
        if (result.code === 0) {
            updateProgress(result.data.progress, result.data.status);
            
            if (result.data.status === 'completed') {
                clearInterval(interval);
                displayImages(result.data.files);
                loadHistory(); // 刷新历史记录
            } else if (result.data.status === 'failed') {
                clearInterval(interval);
                alert('任务失败: ' + result.data.error);
            }
        }
    }, 1000); // 每秒轮询一次
}

// 加载历史记录
async function loadHistory() {
    const response = await fetch(`${API_BASE}/tasks?page=1&page_size=20`, {
        headers: {
            'Authorization': `Bearer ${token}`
        }
    });
    const result = await response.json();
    
    if (result.code === 0) {
        renderHistoryList(result.data.tasks);
    }
}

// 显示历史记录详情
function showHistoryDetail(task) {
    // 显示模态框，展示任务详情和图像
    const modal = document.getElementById('historyModal');
    const detail = document.getElementById('historyDetail');
    
    detail.innerHTML = `
        <p>创建时间: ${task.created_at}</p>
        <p>状态: ${task.status}</p>
        <div class="history-images">
            ${task.files.map(file => `
                <div class="image-item">
                    <img src="${file.url}" alt="${file.filename}">
                    <button onclick="downloadImage('${file.url}', '${file.filename}')">下载</button>
                </div>
            `).join('')}
        </div>
    `;
    
    modal.style.display = 'block';
}

// 下载图像
function downloadImage(url, filename) {
    const link = document.createElement('a');
    link.href = url;
    link.download = filename;
    link.click();
}

// 页面加载时初始化
window.addEventListener('DOMContentLoaded', init);
```

#### 3.3.3 任务调度模块
**功能**：
- 接收前台任务请求
- 任务队列管理（支持并发控制）
- 任务状态同步（前台 ↔ ComfyUI）
- 任务结果回调
- 记录生成请求到数据库（generation_requests表）

**任务处理流程**：
1. 接收前台任务请求（通过 WebSocket）
2. 验证用户权限（可选，由前台保证）
3. **记录生成请求**：将请求信息保存到数据库（generation_requests表）
   - 记录用户信息（user_id, device_id）
   - 记录提示词和工作流信息
   - 记录请求时间
4. 提交任务到 ComfyUI，获取 prompt_id
5. 更新数据库记录：添加 prompt_id，更新状态为 running，记录 started_at
6. 监听 ComfyUI WebSocket，跟踪任务状态
7. 任务完成时下载图像
8. 更新数据库记录：添加文件信息（files_info），更新状态为 completed，记录 completed_at
9. 通过 WebSocket 通知前台任务完成

**生成请求记录数据结构**：
```go
type GenerationRequest struct {
    ID             int64     `json:"id"`
    RequestID      string    `json:"request_id"`      // 对应前台的task_id
    UserID         int64     `json:"user_id"`
    DeviceID       string    `json:"device_id"`
    PromptID       string    `json:"prompt_id"`
    PromptText     string    `json:"prompt_text"`     // 正向提示词
    NegativePrompt string    `json:"negative_prompt"` // 负向提示词
    Workflow       string    `json:"workflow"`        // JSON格式的工作流
    Status         string    `json:"status"`
    Progress       int       `json:"progress"`
    Error          string    `json:"error,omitempty"`
    FilesInfo      string    `json:"files_info"`      // JSON格式的文件信息
    CreatedAt      time.Time `json:"created_at"`
    StartedAt      *time.Time `json:"started_at,omitempty"`
    CompletedAt    *time.Time `json:"completed_at,omitempty"`
    UpdatedAt      time.Time `json:"updated_at"`
}
```

**提示词提取说明**：
- 从工作流JSON中提取正向提示词和负向提示词
- 通常在工作流的CLIPTextEncode节点中
- 正向提示词：positive节点的text字段
- 负向提示词：negative节点的text字段

## 4. 数据流设计

### 4.1 用户提交任务流程

```
用户 → 前台HTTP API → 前台任务管理 → 前台WebSocket → 中台WebSocket
                                                          ↓
中台任务调度 → ComfyUI HTTP API → ComfyUI WebSocket → 中台监听
                                                          ↓
中台下载图像 → 中台文件服务器 → 中台WebSocket → 前台WebSocket → 用户
```

### 4.2 详细流程说明

#### 4.2.1 用户初始化流程
1. **首次访问**：用户访问前台服务
2. **设备ID检查**：
   - 客户端检查LocalStorage/Cookie中是否有device_id
   - 如果没有，生成新的device_id并存储
3. **用户初始化**：
   - 客户端调用 `/api/user/init`，携带device_id
   - 前台检查数据库中是否存在该device_id的用户
   - 如果不存在，自动创建游客用户
   - 生成JWT Token返回给客户端
4. **Token存储**：客户端存储Token，后续请求携带Token

#### 4.2.2 任务提交流程
1. **用户请求**：用户通过 HTTP API 提交任务（包含工作流 JSON，携带Token）
2. **前台处理**：
   - 验证用户 Token，获取用户ID
   - 如果Token无效，引导用户重新初始化
   - 创建任务记录（状态：pending，关联user_id）
   - 生成任务ID
   - 通过 WebSocket 发送任务到中台
3. **中台处理**：
   - 接收任务请求
   - 提交到 ComfyUI，获取 prompt_id
   - 通过 WebSocket 返回 prompt_id 给前台
   - 开始监听 ComfyUI WebSocket
4. **前台更新**：
   - 更新任务状态为 running
   - 记录 prompt_id
   - 更新用户最后活跃时间

#### 4.2.3 任务执行流程
1. **ComfyUI 执行**：
   - ComfyUI 通过 WebSocket 推送进度消息
   - 中台接收并解析消息
2. **中台转发**：
   - 中台通过 WebSocket 转发进度给前台
   - 前台更新任务进度
3. **图像生成完成**：
   - ComfyUI 推送 executed 消息（包含图像信息）
   - 中台下载图像到本地存储
   - 生成图像访问URL
   - 通过 WebSocket 通知前台图像就绪

#### 4.2.4 任务完成流程
1. **中台处理**：
   - 收到 execution_success 消息
   - 确认所有图像已下载
   - 通过 WebSocket 发送任务完成消息给前台
2. **前台处理**：
   - 更新任务状态为 completed
   - 记录图像URL列表
   - 通过 HTTP API 返回给用户（如果用户正在轮询）

#### 5.0.3 JWT认证中间件
```go
package middleware

import (
    "github.com/gin-gonic/gin"
    "github.com/golang-jwt/jwt/v5"
    "strings"
)

func AuthMiddleware() gin.HandlerFunc {
    return func(c *gin.Context) {
        authHeader := c.GetHeader("Authorization")
        if authHeader == "" {
            c.JSON(401, gin.H{"code": 401, "message": "未授权"})
            c.Abort()
            return
        }
        
        // 提取Token
        parts := strings.Split(authHeader, " ")
        if len(parts) != 2 || parts[0] != "Bearer" {
            c.JSON(401, gin.H{"code": 401, "message": "Token格式错误"})
            c.Abort()
            return
        }
        
        tokenString := parts[1]
        
        // 验证Token
        token, err := jwt.Parse(tokenString, func(token *jwt.Token) (interface{}, error) {
            return []byte(config.GetJWTSecret()), nil
        })
        
        if err != nil || !token.Valid {
            c.JSON(401, gin.H{"code": 401, "message": "Token无效"})
            c.Abort()
            return
        }
        
        // 提取用户信息
        claims, ok := token.Claims.(jwt.MapClaims)
        if !ok {
            c.JSON(401, gin.H{"code": 401, "message": "Token解析失败"})
            c.Abort()
            return
        }
        
        // 将用户ID存储到上下文
        userID := int64(claims["user_id"].(float64))
        deviceID := claims["device_id"].(string)
        c.Set("user_id", userID)
        c.Set("device_id", deviceID)
        
        c.Next()
    }
}
```

```go
func CreateTask(c *gin.Context) {

    // 创建任务记录

        c.JSON(500, gin.H{"code": 500, "message": "创建任务失败", "error": err.Error()})

    // 通过WebSocket发送任务到中台

        return

        "code": 0,
        "message": "success",
        "data": gin.H{
            "task_id": task.ID,
            "status": task.Status,
        },
```

### 6.3 SQLite 特殊说明

1. **时间戳处理**：
   - SQLite 不支持 `ON UPDATE CURRENT_TIMESTAMP`
   - 需要在应用层手动更新 `updated_at` 字段
   - 使用 `DATETIME DEFAULT CURRENT_TIMESTAMP` 设置默认值

2. **JSON 存储**：
   - SQLite 3.38+ 支持 JSON 函数，但存储时使用 TEXT 类型
   - 可以使用 `json_extract()` 函数查询 JSON 字段
   - 或者使用应用层解析 JSON

3. **外键约束**：
   - 需要在连接时启用：`PRAGMA foreign_keys = ON;`
   - SQLite 默认关闭外键约束

4. **数据库文件位置**：
   - 前台数据库：`./data/front.db`
   - 中台数据库：`./data/middle.db`（用于记录生成请求）

## 7. 安全设计

### 7.1 用户识别与安全
- 设备ID生成：使用UUID v4生成唯一设备ID，存储在客户端LocalStorage/Cookie
- JWT Token 设置过期时间（如 30 天，游客用户可设置更长）
- Token 包含用户ID和device_id，用于用户隔离
- API 接口需要 Token 验证
- 用户信息持久化：记住用户的设备ID、昵称、历史任务等信息
- 定期清理：可设置清理策略，清理长期未活跃的游客用户数据（如90天未活跃）

### 7.2 用户隔离与信息记忆
- **用户隔离**：
  - 所有任务操作都关联 user_id
  - 数据库查询强制添加 user_id 条件
  - 图像文件按 user_id 目录隔离存储
  - 图像访问接口验证用户权限
- **信息记忆**：
  - 用户信息持久化：device_id、昵称、头像等信息存储在数据库
  - 任务历史记忆：用户的所有任务记录都会保存，可随时查看
  - 跨会话恢复：用户通过device_id自动识别，恢复历史数据
  - 活跃度跟踪：记录用户最后活跃时间，用于数据清理和统计

### 7.3 中台连接安全
- 中台连接前台时使用密钥认证
- WebSocket 连接使用 WSS（TLS加密）
- 心跳检测，异常连接自动断开

### 7.4 数据安全
- 敏感信息不记录日志
- 图像文件访问权限控制
- SQL 注入防护（使用参数化查询）
- XSS 防护（输入验证和转义）

## 12. 客户端实现说明

### 12.1 设备ID生成与存储（前端）

**JavaScript示例**：
```javascript
// 生成或获取设备ID
function getOrCreateDeviceID() {
    let deviceID = localStorage.getItem('device_id');
    if (!deviceID) {
        // 生成UUID v4
        deviceID = 'xxxxxxxx-xxxx-4xxx-yxxx-xxxxxxxxxxxx'.replace(/[xy]/g, function(c) {
            const r = Math.random() * 16 | 0;
            const v = c === 'x' ? r : (r & 0x3 | 0x8);
            return v.toString(16);
        });
        localStorage.setItem('device_id', deviceID);
    }
    return deviceID;
}

// 用户初始化流程
async function initUser() {
    const deviceID = getOrCreateDeviceID();
    const response = await fetch('/api/user/init', {
        method: 'POST',
        headers: {
            'Content-Type': 'application/json',
        },
        body: JSON.stringify({
            device_id: deviceID,
            nickname: ''  // 可选
        })
    });
    
    const result = await response.json();
    if (result.code === 0) {
        // 存储Token
        localStorage.setItem('token', result.data.token);
        localStorage.setItem('user_id', result.data.user.id);
        return result.data;
    }
    throw new Error(result.message);
}

// 获取Token（用于API请求）
function getToken() {
    return localStorage.getItem('token');
}

// 检查Token是否有效，无效则重新初始化
async function ensureUser() {
    const token = getToken();
    if (!token) {
        return await initUser();
    }
    
    // 验证Token是否有效
    try {
        const response = await fetch('/api/user/info', {
            headers: {
                'Authorization': `Bearer ${token}`
            }
        });
        if (response.ok) {
            return await response.json();
        }
    } catch (e) {
        // Token无效，重新初始化
    }
    
    return await initUser();
}
```

**使用流程**：
1. 页面加载时调用 `ensureUser()` 确保用户已初始化
2. 所有API请求携带Token：`Authorization: Bearer {token}`
3. 设备ID持久化存储在LocalStorage，跨会话有效
